## 1. 6軸の定義（名称と説明は暫定）

名称と説明文は `demoDilemmas.ts` の `UI_VALUE_AXES` のまま変えていない。人の承認（中立性の点検を含む）は済んでいない。

| 軸ID | 名称 | 意味（画面の説明文） | A側に出る質問 | B側に出る質問 |
| --- | --- | --- | --- | --- |
| `FAIRNESS` | 公平性 | 住む場所や事情にかかわらず、同じようにサービスを受けられることを大切にする考え方 | `demo-dilemma-transport`（地域交通） | `demo-dilemma-healthcare`（医療・福祉） |
| `STABILITY` | 暮らしの安定 | 今の暮らしや負担の見通しが立つことを大切にする考え方 | `demo-dilemma-education`（教育・子育て） | `demo-dilemma-transport`（地域交通） |
| `FUTURE` | 将来への投資 | すぐに成果が出なくても、先の世代や地域の将来のために取り組むことを大切にする考え方 | `demo-dilemma-economy`（地域経済・雇用） | `demo-dilemma-population`（人口減少・地域活性化） |
| `OPPORTUNITY` | 個人の可能性 | 一人ひとりが学んだり挑戦したりする機会が広がることを大切にする考え方 | `demo-dilemma-population`（人口減少・地域活性化） | `demo-dilemma-education`（教育・子育て） |
| `COMMUNITY` | 地域のつながり | 住民どうしや地元の事業者の結びつきで、地域を支えることを大切にする考え方 | `demo-dilemma-disaster`（防災） | `demo-dilemma-economy`（地域経済・雇用） |
| `INFRASTRUCTURE` | 公共基盤の充実 | 施設・設備・拠点など、形のある共通の基盤を整えることを大切にする考え方 | `demo-dilemma-healthcare`（医療・福祉） | `demo-dilemma-disaster`（防災） |

**A側・B側の意味**: 質問ごとに、考え方Aと考え方Bの2つの軸を比べる。軸がA側に出る質問では「Aを重視」がその軸の側、B側に出る質問では「Bを重視」がその軸の側になる。AとBに優劣はない。

**6テーマと6軸は別の概念**である。

| | 6テーマ | 6軸 |
| --- | --- | --- |
| 何か | 地域課題の分野（地域交通、教育・子育てなど）。契約の `ThemeId` | 2つの考え方を比べるときの見方（公平性、暮らしの安定など）。v2の画面専用の仮の型 `UiValueAxisId` |
| 質問との関係 | 1問は1テーマに属する | 1問は2つの軸（A側とB側）にかかわる。1つの軸は2つのテーマの質問に出る |
| 結果の表し方 | 地域課題マップ（1問＝1行。5段階の位置と回答の振り返り。テーマの回答は合算しない） | 価値観レーダー（軸ごとの水準 −2〜+2） |

## 2. 回答値と寄与

| 回答 | 符号つきの値 s | A側の軸への寄与 | B側の軸への寄与 |
| --- | --- | --- | --- |
| `A_STRONG`（Aを強く重視） | +2 | +2 | −2 |
| `A_LEAN`（Aをやや重視） | +1 | +1 | −1 |
| `BALANCED`（同程度） | 0 | 0 | 0 |
| `B_LEAN`（Bをやや重視） | −1 | −1 | +1 |
| `B_STRONG`（Bを強く重視） | −2 | −2 | +2 |
| `SKIPPED`（スキップ） | なし | 計算に入れない | 計算に入れない |
| 未回答（キーがない） | なし | 計算に入れない | 計算に入れない |

「同程度」は回答として数える（0の寄与を持つ1問）。スキップと未回答は、0点にも「同程度」にもしない。

## 3. 計算式

軸 X について、X が現れる質問のうち、回答のある質問（5段階のどれか）だけを使う。

- n = 寄与の合計（整数）
- m = 回答のある質問の数（重みはすべて1）
- 得点 = R(n, m) = floor((200n + m) / (2m))。n / m × 100 を整数に丸める（ちょうど0.5は正の方向へ）。−200〜+200
- 水準 = 得点が t2 以上なら +2、t1 以上なら +1、−t1 より大きければ 0、−t2 より大きければ −1、それ以外は −2。t1 = 50、t2 = 150

R と段階の規則と境目は、既存の価値観マップ（`packages/domain/src/regional-values/map/rounding.ts` の `roundRatio` と `levelOf`、`config/regional-values/map.json` の `thresholds`）と同じである。

現在の6問では、各軸の質問は2問なので、得点と水準は次の表で決まる。

| 回答のある質問 | 寄与の合計 n | 得点 | 水準 |
| --- | --- | --- | --- |
| 2問 | −4、−3 | −200、−150 | −2 |
| 2問 | −2、−1 | −100、−50 | −1 |
| 2問 | 0 | 0 | 0 |
| 2問 | +1、+2 | +50、+100 | +1 |
| 2問 | +3、+4 | +150、+200 | +2 |
| 1問 | −2、−1、0、+1、+2 | −200、−100、0、+100、+200 | −2、−1、0、+1、+2 |
| 0問 | — | なし | なし（分析できない） |

**レーダー上の表示**: 水準 −2 が内側、0 が真ん中の六角形、+2 が外枠。外側ほど「その軸の考え方の側を選んだ」、内側ほど「比べた相手の考え方を選んだ」を表す。得点は画面に出さない。

## 4. 状態と、計算できない条件

| 状態 | 条件 | 画面 |
| --- | --- | --- |
| `DETERMINED` | 回答のある質問が1問以上 | 点を置く。1問だけのときは「（1問から）」と出す |
| `UNDETERMINED` | 軸の質問はあるが、回答のある質問が0問。理由 `reasons` に、`SKIPPED` と `UNANSWERED` を、この順で、あったものだけ持つ | 点を置かず、軸を点線にし、「分析できません（…スキップしました／…未回答です／…スキップと未回答です）」と出す |
| `NOT_ASKED` | この診断に、軸の質問がない（未出題） | 点を置かず、軸を点線にし、「未出題」と出す |
| `INVALID`（分析全体） | 質問、軸、回答に誤りがある（下の表） | レーダーを描かず、表示できないことを示す。サンプル表示にも切り替えない |

入力の誤り（`INVALID`。すべてを、入力の順で返す）

| 理由コード | 条件 |
| --- | --- |
| `DUPLICATE_AXIS_ID` | 軸の一覧に同じ軸IDが2回ある |
| `DUPLICATE_QUESTION_ID` | 質問に同じ質問IDが2回ある |
| `UNKNOWN_AXIS_ID` | 考え方の軸が、軸の一覧にない |
| `SAME_AXIS_ON_BOTH_SIDES` | 考え方AとBが同じ軸 |
| `UNKNOWN_QUESTION_ID` | 回答の質問IDが、質問にない（質問IDの順） |
| `INVALID_ANSWER_VALUE` | 回答の値が、5段階と `SKIPPED` のどれでもない（`UNSURE`、`DECLINE` も拒否） |

v1の無意見の回答との関係: v1の契約は「わからない」（`UNSURE`）、「回答しない」（`DECLINE`）、「未回答」（`UNANSWERED`）、「未出題」（`NOT_ASKED`）を分ける。v2の画面は、「わからない」と「回答しない」を「スキップ」（`SKIPPED`）1つにまとめている（UI担当の以前の指示）。本仕様は、スキップ、未回答、未出題の3つを分けて持ち、どれも0点や「同程度」にしない。「わからない」と「回答しない」を分けるかは、v2の契約で共同開発者が決める（`real-data-readiness-review.md` 4.6）。

## 5. 判断の理由と代替案

| 論点 | 採用 | 代替案 | 理由 |
| --- | --- | --- | --- |
| 丸め | 既存の R(n, m) と段階の境目（t1 = 50、t2 = 150） | (a) 4.6の案「平均を0から遠い側へ丸める」。(b) 合計 n をそのまま水準にする（−4〜+4を切り詰める） | 既存の価値観マップと同じ規則で、境目の値が設定ファイルで承認済み。(a) は、1問が「やや」でもう1問が「同程度」（平均0.5）を+1にし、2問が逆向き（−2と+1）を−1にする点は採用案と同じだが、新しい丸め規則を増やす。(b) は1問だけの軸と2問の軸で尺度が変わる |
| 「同程度」 | 回答として数える（寄与0） | 計算に入れない | 利用者が選んだ回答で、スキップとは意味が違う（4.6の案と同じ） |
| 1問だけの軸 | その1問から計算し、「（1問から）」と示す | 分析できないにする | 回答の事実を捨てない。根拠の問数を画面で示す（v2の部品がすでに表示する） |
| 計算の場所 | v2専用の純関数 `computeValueAxes`（web） | `generateValuesMap` を使う。domain に新しい関数を足す | `generateValuesMap` は v1 の質問（大切さと優先条件をテーマごとに分ける）を入力にし、1問が2軸にかかわる v2 には使えない。domain への追加と、web から domain を読み込む依存の宣言は、v2の契約と一緒に共同開発者が決める事項（4.5） |
| 重み | すべて1 | 質問ごとの重み | v2の質問に重みの項目がない |

**守る性質**（`axisAnalysis.test.ts` で検査する）

1. 5段階と寄与の対応（2の表）と、6軸それぞれについて、2問の回答の25通りと片方だけの回答の10通りの水準（3の表）。
2. 段階の規則が、得点 −200〜+200 のすべてで、domain の `levelOf` と一致する。境目が `map.json` と一致する。
3. スキップと未回答は寄与を持たず、0点にならない。分析できない軸は、得点も水準も持たない。
4. スキップ、未回答、未出題を区別する。
5. 同じ入力からは同じ結果を返す。回答の対応の列挙順によらない。入力を書き換えない。
6. 1問の回答を変えると、その質問の2つの軸だけが変わりうる（ほかの4軸は変わらない）。答え直すと、新しい回答から計算し直す。
7. 質問の考え方AとBを入れ替え、回答も左右を入れ替えると、どの軸の結果も同じになる。
8. すべて回答すると、6軸の寄与の合計は0になる（全部の軸を外側にはできない。画面の説明と一致する）。
9. 不正な質問ID、回答値、軸の誤りを拒否し、値を作らない。
10. 各軸の結果が、根拠（質問、考え方の側、比べた相手の軸、回答、寄与）を質問の提示順に持ち、得点が根拠の寄与だけから決まる。

**使わないもの**: 事実項目、出典、課題、対応の記録、AIの出力、時刻、乱数。回答は画面の状態にだけ持ち、保存も送信もしない（既存の v2 の方針のまま）。

## 6. 画面への接続

- 結果画面の既定の分析を `analyzeValueAxes`（= `computeValueAxes`）にした。回答に応じてレーダーの形が変わる。答え直すと、結果画面を開くたびに今の回答から計算し直す。
- サンプル表示との切替: 分析の結果が `ANALYZED` のときだけ、回答から計算した値で描く（`data-radar-mode="analysis"`）。`INVALID` のときは図を描かない。サンプル表示（`SAMPLE_AXIS_VALUES`）は、差し替えた分析の関数が `PENDING` を返したときと、開発用プレビューの `#radar-sample`（診断の代わりにサンプルの欄だけを出す）にだけ使う。同じ画面に、分析結果とサンプルの値を並べない。
- 値の多角形は半透明の青で塗る（共同開発者の変更 `d3491f3` のまま。理由は「利用者の指示」と記録されている）。図の下で「面積の大きさに意味はなく、順位でもない」「全部の軸を外側にすることはできない」と説明する。
- 「6つの考え方」の欄に、軸ごとの分析の文と、各質問の「比べた相手」と「この軸への反映」（この考え方の側へ強く／やや、比べた相手の側へ強く／やや、どちらにも動かしていない、計算に入れていない）を出す。
